# 放心借 lookalike：样本表补征信特征

## 背景

| 表 | 说明 |
| --- | --- |
| `lj_iceberg.ai_decision_dev.fxj_ayh_seed_users_expansion_tx_cpd_fpd_bh_rzdz_pd_multiloans_feature` | 扩量样本宽表（已含放心借 / 腾讯 / 百行 / 朴道等），**缺征信** |
| `..._feature_with_credit` | 本脚本产出：在样本表基础上挂**最近一次报告**的征信特征 |

同事口头约定：

- `days_dt_zx`、`dt_zx` 已在样本侧定义为**最近一次征信报告**时间，本脚本**不再**按时间窗 `row_number` 选报告。
- **不增加马消（安逸花）特征**（种子用户大量非马消客户）。
- 征信加工口径与「预测有余额流失用户未来借贷需求」项目中 `sql/run_all_20260715.sql` Part 3~4 一致（循环贷 R1/R2/R3、剔马消机构码 `T10156530H0001`）；此处为**单报告快照**，不做 1m/6m/1y 多报告窗口聚合。

## 脚本位置

| 文件 | 用途 |
| --- | --- |
| `sql/同事样例_安逸花放心借分析.sql` | 同事 yanyan.zheng 提供的探索与中间表样例（归档） |
| `sql/fxj_seed_users_attach_credit_feature.sql` | **正式加工**：spine → 账户明细 → 报告聚合/扩展 → 挂回样本 |

## 运行顺序

1. 确认样本表已就绪，且主键字段为 `unique_id`（与征信 `id_unqp` 一致）；`dt_zx` 为 `yyyyMMdd` 字符串。
2. 在集群按段执行 `fxj_seed_users_attach_credit_feature.sql`（Part 0 探查 → Part 6 核验）。
3. 查看核验 SQL：`has_zx_feature_cnt` 与 `has_dt_zx_cnt` 对比，排查 `dt_zx` 在 PBOC 分区中无账户/无 summary 的个案。

## 中间表（可删）

- `fxj_seed_zx_spine`
- `fxj_seed_credit_account_base`
- `fxj_seed_credit_report_agg`
- `fxj_seed_credit_billday_agg`
- `fxj_seed_credit_report_ext`

## 与 jcr 项目的关系

- `jcr_credit_*_20260715` 仅覆盖 **jcr cohort** 用户；放心借种子人群需单独跑 `fxj_seed_*` 中间表，不能假定直接 join jcr 表即有数据。
- 若同一 `unique_id + dt_zx` 同时出现在 jcr 与 fxj 流水线，聚合字段应与 `jcr_credit_report_agg_20260715` 一致（脚本末尾留有可选交叉验证 SQL）。

## 字段命名

产出征信列使用 `latest_*` 前缀，与 `jcr_credit_feature_20260715` 中「最近一份报告」口径对齐，便于后续建模特征清单复用。
