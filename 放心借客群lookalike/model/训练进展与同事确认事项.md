## 一、业务目标（简要）

在**安逸花/放心借扩量背景人群**中，学习**低定价放心借种子用户**（正类 P）的特征共性，输出 lookalike 评分用于营销扩量。

| 角色 | 业务定义 |
|------|----------|
| **P（pu_label=1）** | 放心借利率 &lt; 18%，且借款当日有征信报告 |
| **U（pu_label=0）** | 背景扩量人群（含隐藏正例） |

当前训练数据主要来自同事表 **`zyy_fxj_ayh_seed_users_expansion_samples`**（约 **21.5 万正 + 50 万负**，已抽样），而非全量千万级背景宽表。

### 2.4 内存优化（128G 分析机曾 OOM，已做如下改造）

| 优化项 | 说明 | 配置位置 |
|--------|------|----------|
| **Parquet 列裁剪** | 只读白名单相关列，不读 6000+ 全宽表 | `feature_list_path` |
| **float32 矩阵** | 用 numpy float32 替代 pandas float64 宽表 | `training.memory.use_float32` |
| **分步释放 DataFrame** | 建好 `x_train` 后释放 `train_df` / `df` | `release_dataframes` |
| **LightGBM free_raw_data** | Dataset 建好后释放原始矩阵 | `lgb_free_raw_data` |
| **仅 val early stopping** | 不在 train 上挂验证集 | `valid_on_val_only` |
| **跳过 train 全量 predict** | 只算 val 指标 | `skip_train_metrics` |
| **max_bin=127** | 降低直方图内存（默认 255） | `memory.max_bin` |
| **num_threads=2** | 限制 LightGBM 线程 | `params.num_threads` |
| **半量 SQL 抽样** | 可选 35 万行训练集 | `tagged_half.sql` + `config_half.yaml` |
| **weighted_naive** | 半量配置默认用原生 lgb（比 elkanoto 省内存） | `config_half.yaml` |

优化后全量训练内存粗算（71.5 万 × 4437 特征）：

- `x_train`（float32）≈ **4.7 GB**（train 经 U 下采样后约 28.4 万行）
- `x_val` ≈ **1.2 GB**

---

### 2.5 训练时 U 下采样说明

当前全量配置 `config.yaml`：

```yaml
unlabeled_subsample_ratio: 0.2
```

含义：**train 集里正类全保留**，**未标注 U 只随机保留 20%**（验证集 val 不下采样）。

因此一次成功训练日志为：

- 全量 715,322 行
- **train = 283,782**（约全表 40%，其中 U 约 1/5）
- **val = 71,160**（约 10%，9:1 划分）

若需 **50 万负样本全参与训练**，需改为 `unlabeled_subsample_ratio: 1.0`（内存会上升，预估 `x_train` 约 15～18 GB）。

## 八、附录：为何「elkanoto + 已标 0/1 表」比真 PU 容易？

| | **当前同事表** | **真实 lookalike / PU** |
|--|----------------|-------------------------|
| 负样本含义 | 50 万**明确标为负** | 千万级**未标注**，含大量隐藏正例 |
| 学习任务 | 区分「给定正 vs 给定负」 | 在未知人群中找「像种子」 |
| Elkanoto 假设 | 算法假设 U 是未标注池 | 实际 U 是硬负例，假设不匹配 |
| 预期 AUC | 容易偏高（表内可分性强） | 通常明显更低，需业务指标验收 |

因此：**当前 0.996 更适合解读为「同事样本表内区分度」**，不能直接等同于「全量背景扩量效果」。
