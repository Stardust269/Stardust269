## 1. 背景与问题定义

### 1.1 业务现象（放心借当前）

| 观察 | 说明 |
| --- | --- |
| 离线指标很好 | test AUC 高、TGI 高百分位 recall 高 |
| 分数分布极尖 | 高分用户高度集中在极窄头部（如前 0.1%～1%） |
| 各 TGI 档位不均匀 | 种子大量挤在最前几档，中后档位「无种可撒」 |
| 扩散困难 | 难以把模型产出当作「可嵌入人群的种子」做规模化扩量 |

### 1.2 形式化描述

设全量候选用户池为 $U$，模型输出分数 $s(u)$，按降序排名得百分位 $r(u) \in [0,1]$。

**判别力（Discrimination）**：用 AUC、KS、Top-K precision 衡量「能否把种子从背景中挑出来」。

**可扩散性（Diffusibility / Reach）**：用分档均匀度、覆盖度、有效 reach 衡量「能否在较宽百分位带内稳定找到足够多、足够像种子的用户」。

二者存在张力：

$$\text{Discrimination} \uparrow \quad \Leftrightarrow \quad \text{Score concentration at top} \uparrow \quad \Rightarrow \quad \text{Diffusibility} \downarrow$$

这不是单纯的技术 bug，而是 **lookalike 分类范式下的结构性权衡**。

### 1.3 与「模型过好」的关系

同事反馈「效果过于好」需拆成两层理解：

| 层面 | 可能含义 | 是否需要担心 |
| --- | --- | --- |
| **真实强信号** | 种子与背景确有强可分特征 | 好现象，但需控制扩量口径 |
| **过拟合/泄漏** | 少量规则即可近乎分开种子（决策树探查已观察到） | 需排查，AUC 可能「虚高」 |
| **目标错配** | 模型优化的是排序头部，不是均匀扩散 | 需改评估与落地方式 |

**结论**：问题不一定是「模型训错了」，更可能是 **训练目标、评估指标、落地方式** 与 **「种子扩散」业务目标** 未对齐。

## 2. 业界是否遇到过类似问题

### 2.1 广告与 MarTech 平台（公开产品文档）

| 平台 | 现象/表述 | 典型做法 |
| --- | --- | --- |
| **Meta Lookalike** | 1% 最像种子、10% 更广更松；相似度随比例扩大而下降 | `ratio` 1%～20% 分档；`starting_ratio` + `ratio` 做非重叠 band（如 1%～2%） |
| **Hightouch** | 提供 Top 10%/20%/50% 相似度分桶，观察「相似度在顶部的集中程度」 | 百分位分桶 + 与源人群组合筛选 |
| **Lytics** | 明确建议：预测分布偏斜时，用 **Percentile** 而非原始 Prediction 切人群 | `Lookalike Model Percentiles` 字段 |
| **Perion / Latentview** | 1% LAL 精度最高但 reach 有限；5%～10% 用于 scaling | 从 1% 逐步扩到 3%、5%，监控 CPA 拐点 |

**行业共识**：lookalike **本来就不是一个分数打天下**，而是 **分层扩量（tiered expansion）**。

### 2.2 学术论文与工业界实践

| 来源 | 核心观点 | 与本文关系 |
| --- | --- | --- |
| **Pinterest, KDD 2019** — *Finding Users Who Act Alike* | 单广告主从零训分类器易过拟合；采用 **全站预训练 embedding + 种子轻量适配** 的两阶段方案 | 直接对应「尖峰 + 难扩散」 |
| **阿里巴巴, KDD 2021** — *MeTa-LAHE* | 单 campaign 一阶段模型对种子集过拟合；用 **元学习 + 多 campaign 共享表示** 提升泛化 | 大规模广告 lookalike 标配思路 |
| **Rakuten / GLoM（CEUR-WS 2024）** | 一阶段 per-campaign 训练耗时且过拟合；两阶段预训练 + 微调；种子过小性能下降 | 种子规模与扩展稳定性 |
| **阿里云开发者社区 — 品牌潜客** | 同时优化 **相似度** 与 **覆盖度（Coverage）**；负样本构造影响扩展形状 | 国内金融/电商可读案例 |
| **AAAI 2022** — *Calibrated Probabilities with Personalized Ranking Models* | 排序模型分数分布左偏、类间方差不同；需 **Gamma/Gaussian 校准** 而非简单 Platt | 分数后处理理论依据 |

### 2.3 国内公开资料

| 来源 | 要点 |
| --- | --- |
| 腾讯云开发者社区 — Lookalike 概述 | Lookalike 是方法族统称：画像匹配、监督分类、图扩散 |
| CSDN — 目标人群优选案例 | **覆盖度** = 用 A 扩出的人群对 B 的恢复比例；**相似度** 用 sigmoid 映射到 $[0.5, 1)$ 供运营设阈值 |
| AI Master — Lookalike 面试题 | 小种子易过拟合；应看扩展档位衰减；警惕把全量当纯负样本 |

**小结**：**国内外都遇到过**「高精度 + 窄扩展」问题；解法高度一致：**分层、校准、两阶段表示、覆盖度指标、种子质量**。

## 3. 根因分析

### 3.1 范式层：分类 vs 相似度

| 范式 | 学什么 | 分数分布典型形态 | 扩量表现 |
| --- | --- | --- | --- |
| **监督分类**（LR/GBDT，种子 vs 非种子） | 决策边界 | 头部极尖、长尾平坦 | Top 精准，中部稀疏 |
| **相似度/Embedding**（Cosine、双塔） | 空间距离 | 相对平滑 | 更适合逐档外扩 |
| **聚类/GMM** | 种子所在簇 | 簇内均匀 | 适合「圈状」扩展 |
| **图传播** | 关系扩散 | 取决于网络结构 | 适合社交/关联扩散 |

放心借当前主路径是 **PU + LightGBM 分类**，天然偏向 **高判别、尖峰分布**。

### 3.2 数据与标签层

| 因素 | 机制 | 放心借相关性 |
| --- | --- | --- |
| **PU 学习** | 未标注中混有隐藏正例；模型强化「最像种子」的头部 | 高（weighted_naive） |
| **负样本构造** | 随机负采样 vs 分层负采样 vs 困难负样本 | 影响边界形状 |
| **种子定义** | 种子越「纯」，头部越尖 | 低定价种子 + 征信条件 |
| **时间切分** | 训练/测试窗不同，可能放大头部效应 | 已做时间外评估 |

### 3.3 特征层

| 因素 | 机制 | 放心借相关性 |
| --- | --- | --- |
| **强特征/规则级可分** | 少量特征即可分开 → 分数极端化 | 决策树探查：浅层树即可极高纯度 |
| **特征泄漏** | 等价于记忆标签规则 | 需排查 `ppdi_*`、`bh_*` 等 |
| **高维稀疏 + GBDT** | 易学到「硬规则」组合 | 4437 维表格特征 |

### 3.4 评估层

| 问题 | 后果 |
| --- | --- |
| 只看 AUC / Top-K recall | 团队优化「更尖」的模型 |
| 不看分档均匀度、覆盖度 | 业务「撒种子」需求被忽视 |
| 不看特征分布一致性 | 扩出去的人群画像漂移未发现 |

## 5. 方案详解：运营与产品层

> **特点**：不改模型，最快落地；业界最常用。

### 5.1 Meta 式百分比分档扩量

**做法**：

- 1%：最像种子，高精度低 reach
- 2%～3%：scaling 主力
- 5%～10%：大范围触达，精度下降可接受
- 使用 `starting_ratio` + `ratio` 切 **非重叠 band**（如 1%～2%、2%～4%）

**适用**：已有稳定排序模型，需快速扩量。

**放心借映射**：TGI 表已支持 p99～p00 分档；可显式定义「投放档位」而非单一阈值。

### 5.2 「核 + 圈」双层策略

| 层级 | 人群 | 用途 |
| --- | --- | --- |
| **核（Core）** | Top 0.1%～1% | 高精度识别、验证模型、核心转化 |
| **圈（Ring）** | 1%～5% / 5%～10% | 营销扩散、活动覆盖、lookalike 外扩 |

**扩散逻辑**：核人群作为「新种子」或对圈人群加权，而非用同一个分数阈值覆盖所有人。

### 5.3 多源种子融合

单一种子包易导致扩展形状单一。业界常组合：

- 高价值成交种子
- 高互动/高授信意愿种子
- 品类/渠道子种子

**输出**：多个 lookalike 包 union 或按权重混合，降低单模型尖峰。

### 5.4 百分位运营（Lytics 建议）

**核心**：投放系统读 **Percentile**，不读 raw score。

原因：当 $s(u)$ 分布极度偏斜时，固定分数阈值会导致 reach 极不稳定；百分位在各批次人群上 **人数可控**。

**放心借**：TGI 固定人数分档（46731/46732）本质上已是百分位的工程化实现。

### 5.5 国内「覆盖度」导向运营

阿里云案例中的 **Coverage**：

$$\text{Coverage} = \frac{|B \cap C|}{|B|}$$

其中种子集拆为 $A$、$B$，用 $A$ 扩出 $C$，衡量扩量对「另一半种子」的恢复能力。

**意义**：防止模型只会找「最容易的那一类种子」，而扩不回整体种子分布。

## 6. 方案详解：分数后处理与校准

> **特点**：保留排序能力，调整分数尺度和分布形状；适合「模型不想重训」阶段。

### 6.1 Rank / Percentile 映射

$$r(u) = \frac{\text{rank}(s(u))}{|U|}$$

- **优点**：天然均匀（按人数分位）；与 Meta/Lytics 一致
- **缺点**：丢失绝对概率意义；跨批次需固定排序池或重新算分位

### 6.2 Platt Scaling（Sigmoid 校准）

$$P(y=1|s) = \sigma(a \cdot s + b)$$

- 在验证集上拟合 $a, b$
- **优点**：单调，**不改变排序**（AUC 不变）；稳定
- **缺点**：假设失真为 S 形；对极度左偏分布拟合差

### 6.3 Isotonic Regression（保序回归）

拟合单调阶梯函数 $f(s) \to P(y=1|s)$。

- **优点**：灵活，可修正复杂单调失真
- **缺点**：需要较大验证集；可能引入 ties，影响细粒度排序

### 6.4 Gamma / Gaussian 校准（AAAI 2022）

针对推荐/排序场景分数 **左偏、类间方差不同**，比 Platt 更有表达力。

- **适用**：GBDT 输出在负类上大量挤在低端、正类长尾
- **实施**：验证集上拟合参数化校准器，作为后处理

### 6.5 相似度 Sigmoid 映射（国内实践）

将「与种子质心距离」映射到 $[0.5, 1)$：

$$\text{sim}(u) = 0.5 + 0.5 \cdot \sigma(-\alpha \cdot d(u, \mu_S))$$

运营按 $\text{sim}$ 阈值控制规模，比 raw margin 更平滑。

### 6.6 温度缩放（Temperature Scaling）

$$P_{\text{cal}} = \sigma(s / T)$$

- $T > 1$：分布更平滑（不那么尖）
- 常用于神经网络；对 GBDT margin 可作启发式尝试

### 6.7 方案对比

| 方法 | 保序 | 平滑尖峰 | 需验证集 | 推荐场景 |
| --- | --- | --- | --- | --- |
| Percentile | 近似 | ★★★★★ | 否 | 投放分档 |
| Platt | 是 | ★★☆☆☆ | 是 | 要概率解释 |
| Isotonic | 近似 | ★★★☆☆ | 是（大） | 分布复杂 |
| Gamma/Gaussian | 是 | ★★★★☆ | 是 | 排序模型 |
| 温度缩放 | 是 | ★★☆☆☆ | 是 | 快速试验 |

## 7. 方案详解：建模与算法改造

> **特点**：从中长期改变分数分布形状；成本较高但更治本。

### 7.1 模型正则化与简化

| 手段 | 参数示例 | 预期效果 |
| --- | --- | --- |
| 降低 `max_depth` | 8 → 4～6 | 减少硬规则，分数更平滑 |
| 增大 `min_data_in_leaf` | 200 → 500+ | 叶节点更稳 |
| 增大 `lambda_l2` | 2 → 5～10 | 抑制过拟合 |
| 减少 `num_leaves` | 63 → 31 | 模型更简单 |
| 特征裁剪 | 去掉可疑强特征 | 降低虚高 AUC |

**放心借**：决策树探查 max_depth=4 已显示极强可分性 → 可对照训练 **浅树 GBDT** 看分数分布变化。

### 7.2 负采样策略改造

| 策略 | 说明 | 对分布影响 |
| --- | --- | --- |
| **随机负采样** | 当前基线 | 边界清晰，易尖峰 |
| **分层负采样** | 按城市/渠道/年龄段抽负例 | 边界更平滑，各群更均衡 |
| **困难负样本（Hard Negative）** | 选高分但未标注样本作负例 | 压低中部、拉高区分，可能更尖 |
| **Easy Negative + 少量 Hard** | 混合 | 需调参 |

**注意**：困难负样本可能 **加剧尖峰**，扩量场景需谨慎。

### 7.3 PU 学习参数调整

| 参数 | 方向 | 效果 |
| --- | --- | --- |
| `unlabeled_weight` | 降低（如 0.05 → 0.01） | 弱化「非种子=负」假设，分数可能更平 |
| `unlabeled_subsample_ratio` | 提高 | 更多 U 参与训练，边界更稳 |
| 换 `elkanoto` | 显式估计先验 | 概率意义更清晰 |

### 7.4 相似度 / Embedding 路线

**流程**：

1. 学用户表示 $\mathbf{e}_u$（双塔、矩阵分解、自编码器）
2. 种子质心 $\boldsymbol{\mu}_S = \frac{1}{|S|}\sum_{u\in S}\mathbf{e}_u$
3. 相似度 $s(u) = \cos(\mathbf{e}_u, \boldsymbol{\mu}_S)$
4. ANN（FAISS/HNSW）召回 Top-N

**优点**：分数分布通常比分类概率平滑；适合大规模扩量。

**缺点**：可解释性弱；需足够行为/特征支撑 embedding 质量。

### 7.5 两阶段 Lookalike（Pinterest / 阿里）

```text
Stage 1（离线、全站）：学通用用户表示或基础排序模型
Stage 2（在线、每种子包）：轻量适配（线性层/小 MLP/质心匹配）
```

**解决**：单种子过拟合 → 尖峰过窄 → 难扩散。

**放心借落地形态**：

- Stage 1：全站用户 + 全特征预训练 embedding 或通用 GBDT
- Stage 2：放心借种子微调或质心匹配

### 7.6 聚类扩展（K-Means / GMM）

1. 对候选用户聚类
2. 找「种子占比高」的簇
3. 整簇或邻近簇作为扩展人群

**特点**：扩展形状「成块」，天然比单阈值更均匀；适合画像解释。

### 7.7 图扩散（Label Propagation / GNN）

- 节点：用户；边：社交、设备、共现、相似边
- 从种子出发传播标签/影响力

**适用**：有稳定关系链或关联图；金融场景需合规评估。

### 7.8 多目标与约束优化

联合优化：

$$\max \;\; \alpha \cdot \text{Similarity} + \beta \cdot \text{Coverage} - \gamma \cdot \text{Risk}$$

或在排序中加入 **多样性约束**（如 DPP、MMR），避免扩展人群过度同质。

### 7.9 特征治理（强烈建议并行）

| 动作 | 目的 |
| --- | --- |
| 审计决策树高频特征 | 识别「规则级」变量 |
| 剔除泄漏字段 | `y_loan_base_rate`、`lend_date_sj` 等 |
| 与业务确认 `ppdi_*`、`bh_*` | 是否可入模、是否导致虚假尖峰 |
| 分群验证 | 各城市/渠道分数分布是否一致 |

## 8. 方案详解：评估体系改造

> **核心**：用「扩散可用性」指标驱动迭代，而非只看 AUC。

### 8.1 建议新增离线指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| **Score Gini** | 分数集中度 | 越高越尖，监控尖峰 |
| **分档均匀度** | 各 TGI 档 `种子用户数` 的变异系数 CV | 直接反映「能否撒种」 |
| **Coverage** | 种子 A 扩出人群对种子 B 的恢复率 | 国内实践标准指标 |
| **Recall@固定人数** | 各档固定 N 人时的种子 recall | 与当前 TGI fixed 分档一致 |
| **特征分布 KL** | 扩展人群 vs 种子的画像 KL 散度 | 防画像漂移 |
| **有效 Reach@阈值** | 满足相似度阈值的可用人数 | 业务可投放规模 |

### 8.2 建议新增可视化

1. **分数分布直方图**（全体 / 分渠道）
2. **分位曲线**：横轴百分位，纵轴累计种子 recall
3. **档位柱状图**：各 TGI 档 `种子用户数`（一眼看均匀性）
4. **校准曲线**：预测概率 vs 实际正例率

### 8.3 在线评估

| 实验 | 对比组 |
| --- | --- |
| A/B | 尖峰模型 Top1% vs 分层扩量 1%～5% |
| 业务 | 授信率、借款发起率、风险逾期 |
| 扩散 | 活动后二级转化、裂变系数 |

### 9.1 当前技术栈

| 组件 | 现状 |
| --- | --- |
| 模型 | LightGBM + PU（weighted_naive） |
| 特征 | 同事白名单 4437 维 |

| 已知现象 | 决策树浅层极高纯度；test AUC 很高；分数头部集中 |

### 9.2 问题—方案映射表

| 观察到的问题 | 优先尝试 | 次选 |
| --- | --- | --- |
| 分数挤在 top 0.1% | B 百分位分档 + A 核+圈 | C Gamma 校准 |
| TGI 各档种子不均 | J 分档均匀度监控 + fixed 人数表 | A 分层投放 |
| AUC 过高疑似泄漏 | 7.9 特征治理 + 浅树对照实验 | 重训去特征 |
| 要可对比历史 | 交叉评估（TGI 训 + 过滤前 test） | 已有 config |
| 长期要稳扩展 | G 两阶段 或 F Embedding | I 多目标 |

### 9.3 不建议的做法

| 做法 | 原因 |
| --- | --- |
| 单纯继续推高 AUC | 可能让尖峰更严重 |
| 只用 Top 0.1% 做全量投放 | reach 不足，扩散失败 |
| 忽视特征泄漏排查 | 高指标不可信，上线风险大 |
| 困难负样本无脑加满 | 可能加剧头部集中 |

## 11. 风险与注意事项

### 11.1 为「拉平分布」牺牲过多精度

扩量档位变宽后，单档 precision 必然下降。需与业务约定 **可接受的 recall–precision–reach 三角**。

### 11.2 校准改变排序

Isotonic 可能引入 ties；若必须严格保序，优先 Platt/Gamma/Percentile。

### 11.3 跨批次百分位漂移

不同时间导出的人群池不同，百分位需 **在同一评分批次内** 计算，或定期重算。

### 11.4 合规与公平

扩量人群需通过风险、征信、营销合规审查；关注地域/年龄等公平性。

### 11.5 虚假高分

若根因是泄漏，任何后处理都只是「把错误分数调好看」，不能上线。

## 14. 附录：给同事的一页摘要（可直接复制到飞书）

**问题**：lookalike 模型离线 AUC 很高，但分数集中在极窄头部（约 top 0.1%），TGI 各档种子分布不均，难以作为「可撒入人群扩散的种子」。

**业界结论**：这是 lookalike 常见现象，不是个案。Meta、Lytics、阿里、Pinterest 等均采用 **分层扩量 + 百分位切人 + 覆盖度评估**，而非追求单一分数阈值。

**短期可做（不重训）**：

1. 用百分位/固定人数分档运营，定义核（0.1%～1%）+ 圈（1%～5%）
2. 新增分档均匀度、Coverage 指标
3. 排查特征泄漏（决策树已提示强规则特征）

**中期可做（重训对照）**：

1. 浅树 + 强正则 + 分层负采样
2. Embedding 质心相似度路线
3. 两阶段预训练 + 种子适配

**评估原则**：从「只看 AUC」改为「AUC + 覆盖度 + 分档均匀度 + 风险画像」多指标驱动。
